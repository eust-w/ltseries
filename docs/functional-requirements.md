# ltseries 功能要求与验收文档

本文档定义 ltseries 当前应满足的产品功能、前端页面要求、关键交互、任务记录要求、LumenX 功能对齐要求和验收标准。项目定位是用 Go + Gin + MongoDB + React 复刻并扩展 LumenX 的短剧生产工作流，不使用 Python 服务，不使用 mock、仿真或硬编码生成结果。

## 1. 产品目标

ltseries 是一个短剧/漫画视频生产工作台，支持从剧本文本出发，经过剧本解析、美术方向、资产生成、分镜制作、视频生成、音频生成、成片拼接、分集管理，最终得到可预览和导出的短剧视频。

核心目标：

- 覆盖 LumenX 的核心生产链路。
- 采用 Go 后端、MongoDB 持久化任务和业务数据、React 前端。
- 生成类能力必须走真实 provider 配置。
- 任务成功或失败都必须持久化，并在刷新前端后可恢复。
- 所有图片、视频、音频资产必须可预览、可选择、可修改或可删除。

## 2. 技术边界

### 必选技术

- 后端：Go + Gin
- 数据库：MongoDB
- 任务队列：基于 MongoDB 的任务队列
- 前端：React + TypeScript + Vite
- 媒体拼接：FFmpeg
- AI provider：通过配置接入，默认支持阿里云百炼 / DashScope 兼容能力

### 禁止事项

- 禁止使用 Python 后端。
- 禁止用 mock 数据伪造生成结果。
- 禁止在前端硬编码 API key。
- 禁止在代码中硬编码用户密钥。
- 禁止生成成功后只记录任务、不回写项目资产。
- 禁止刷新页面后丢失任务历史或生成结果。

## 3. 信息架构

前端必须按清晰页面/Tab 拆分，不允许把所有功能堆在单页。

当前项目工作台应包含：

1. 剧本
2. 美术方向
3. 资产
4. 分镜
5. 成片
6. 分集
7. 项目设置

系统级页面应包含：

1. 项目工作台
2. 系统设置
3. 登录/退出

## 4. 核心业务对象

### Project

项目代表单集短剧，必须保存：

- 标题
- 剧本原文
- 工作流：`r2v` / `i2v` / `t2v`
- 剧本分析结果
- 美术方向
- 角色、场景、道具
- 分镜
- 视频任务
- 模型设置
- Prompt 设置
- 拼接成片 URL
- 所属系列与集数

### Series

系列用于组织多集项目，必须保存：

- 系列标题
- 系列描述
- 默认工作流
- 分集项目 ID 列表
- 共享角色/场景/道具字段
- 模型设置与 Prompt 设置

### Entity

资产实体分为：

- 角色：`character`
- 场景：`scene`
- 道具：`prop`

角色必须支持：

- 全身图 `full_body`
- 三视图 `three_views`
- 头像特写 `head_shot`
- 通用参考图 `image`
- 参考视频
- 声音绑定与声音参数

场景和道具必须支持：

- 图片变体
- 当前选中图
- 参考视频
- 锁定状态

### StoryboardShot

分镜必须支持：

- 镜头序号
- 动作描述
- 镜头语言
- 台词
- Prompt
- 参与角色
- 场景 ID
- 分镜图
- 视频
- 视频末帧 `last_frame_url`，用于下一镜头连续性参考
- 音频
- 音效
- 锁定状态
- 当前选中视频

### Task

任务必须持久化：

- 任务 ID
- 任务类型
- 状态
- 进度
- 错误信息
- 项目 ID
- payload
- result
- worker 信息
- 创建/更新/开始/结束时间

任务状态：

```text
pending
processing
completed
failed
```

任务类型：

```text
analysis
art_direction
asset_generation
asset_video
storyboard_analysis
storyboard_render
video_generation
audio_generation
sfx_generation
bgm_generation
merge
storyboard_pipeline
```

### ProductionAudit

生产体检必须返回：

- 总分 `score`
- 效率分 `efficiency_score`
- 一致性分 `consistency_score`
- 是否可预览 `ready_for_preview`
- 是否可交付 `ready_for_export`
- 流程阶段 `workflow_stages`
- 逐镜头一致性抽检 `frame_audits`
- 问题列表 `issues`
- 改进建议 `recommendations`

前端必须在成片页展示生产体检结果，帮助创作者判断当前项目是否达到交付条件。

## 5. LumenX 功能对齐要求

### 5.1 Script

LumenX 能力：

- 输入剧本。
- 自动解析剧情、角色、场景、道具。
- 自动生成初始分镜。
- 剧本原文可编辑。

ltseries 要求：

- 必须支持创建项目并保存剧本原文。
- 必须支持修改剧本原文。
- 必须支持 `analyze` 和 `reparse`。
- 分析成功后必须写回 `analysis`、`characters`、`scenes`、`props`、`frames`、`art_direction`。
- 分析失败必须写入任务错误，不允许吞掉错误。

验收：

- 刷新页面后剧本原文仍存在。
- 解析任务完成后角色/场景/道具/分镜可见。
- 失败任务在任务记录中可见。

### 5.2 Art Direction

LumenX 能力：

- 自动生成艺术方向。
- 可人工调整风格、正向 prompt、负向 prompt、色彩、镜头语言。

ltseries 要求：

- 必须支持自动生成美术方向任务。
- 必须支持人工保存美术方向。
- 必须支持风格预设。
- 美术方向必须参与后续资产和分镜 prompt 组织。

验收：

- `/art-direction` 页面可编辑并保存。
- 刷新后保留已保存的美术方向。

### 5.3 Assets

LumenX 能力：

- 角色、场景、道具管理。
- 角色先生成无背景全身图。
- 基于全身图生成三视图。
- 基于全身图生成头像特写。
- 每类资产支持多变体、选择、锁定。
- 资产可上传、可生成、可预览。
- 资产可生成参考视频。

ltseries 要求：

- 资产页必须拆分角色、场景、道具。
- 角色必须明确展示全身图、三视图、头像特写、通用图四个区块。
- 每个区块必须支持：
  - 生成图片
  - 上传图片
  - 预览图片
  - 选择变体
  - 收藏变体
  - 删除变体
  - 生成参考视频
- 资产卡片必须支持编辑名称和描述。
- 资产必须支持锁定/解锁。
- 一键补齐资产必须按 LumenX 顺序执行：
  - 角色无全身图：生成全身图。
  - 角色已有全身图但无三视图：用全身图作参考生成三视图。
  - 角色已有全身图但无头像：用全身图作参考生成头像。
  - 场景/道具无图：生成主图。
- 锁定资产不得参与批量生成。

验收：

- 上传/生成成功后刷新页面，图片仍能显示。
- 删除变体后刷新页面，变体不再出现。
- 收藏变体后刷新页面，收藏状态仍存在。
- 资产视频任务成功后，资产卡片能预览视频。
- 资产视频可删除。

### 5.4 Storyboard

LumenX 能力：

- 自动拆镜。
- 分镜可人工新增、修改、删除、复制、排序。
- 每个镜头可选择角色/场景/道具引用。
- 可生成分镜图。
- 可上传分镜图。
- 可从视频抽末帧作为下一步参考。
- 可锁定镜头。

ltseries 要求：

- 分镜页必须有 AI 拆镜入口。
- 分镜页必须有手动添加镜头入口。
- 镜头卡片必须支持：
  - 编辑动作
  - 编辑 prompt
  - 保存
  - 复制
  - 删除
  - 锁定/解锁
  - 生成分镜图
  - 上传分镜图
  - 生成视频
  - 生成音频
  - 抽取视频末帧
- 分镜图和视频必须可预览。
- 分镜顺序必须由后端重新编号。

验收：

- 手动新增镜头后刷新页面仍存在。
- 修改镜头后刷新页面仍保留。
- 删除镜头后刷新页面不再出现。
- 复制镜头后出现新镜头 ID。
- 上传分镜图后可预览。
- 抽末帧成功后写入当前镜头分镜图。

### 5.5 Motion / Video

LumenX 能力：

- I2V 首帧生成视频。
- R2V 参考视频生成视频。
- 可生成多条候选视频。
- 可选择最终使用的视频。

ltseries 要求：

- 必须支持 frame video task。
- 必须支持 asset video task。
- 视频生成必须进入 MongoDB 队列。
- 任务完成后必须写回：
  - `project.video_tasks`
  - 对应 `frame.video_url` / `selected_video_id`
  - 或资产 `video_variants`
- 前端必须能预览视频。
- 前端必须能删除资产视频。

验收：

- 视频任务完成后刷新页面仍能预览视频。
- 任务失败后任务记录显示错误。
- 已选视频参与成片拼接。

### 5.6 Audio / SFX / BGM

LumenX 能力：

- 角色声音设置。
- 镜头音频生成。
- 音效生成。
- BGM 生成。

ltseries 要求：

- 角色必须支持绑定声音 ID、声音名称。
- 角色必须支持声音速度、音高、音量。
- 镜头必须支持音频生成。
- 项目必须支持 SFX/BGM 生成任务。
- 没有音频 provider 配置时必须返回真实错误，不允许假音频。

验收：

- 角色声音参数保存后刷新仍存在。
- 音频任务失败时任务记录保留错误。
- 音频任务成功后写回镜头 URL。

### 5.7 Assembly

LumenX 能力：

- 查看每个镜头视频。
- 选择最终镜头视频。
- 拼接生成成片。
- 导出视频。

ltseries 要求：

- 成片页必须展示镜头时间线。
- 必须支持 FFmpeg 拼接。
- 必须支持导出。
- 如果已有 `merged_video_url`，导出应直接返回 URL。

验收：

- 没有视频时拼接失败并记录错误。
- 有视频时拼接任务完成后项目写入 `merged_video_url`。
- 刷新页面后成片仍可预览。

### 5.8 Series / Episodes

LumenX 能力：

- 多集管理。
- 系列级资产和配置。

ltseries 要求：

- 必须支持创建系列。
- 必须支持项目加入系列。
- 必须支持项目移出系列。
- 必须自动维护集数。
- 当前项目必须展示所属系列和集数。
- 系列详情必须可查看 episode 列表。

验收：

- 加入系列后项目出现 `series_id` 和 `episode_number`。
- 移出系列后项目清空系列字段。
- 刷新页面后分集关系仍存在。

## 6. 页面功能要求

### 6.1 登录页

必须包含：

- 用户名输入。
- 密码输入。
- 登录按钮。
- 登录失败提示。

要求：

- 默认用户名可以填 `admin`。
- 密码不得写死在前端逻辑中。
- token 存储在 `localStorage`。
- 退出登录必须清除 token。

### 6.2 系统设置页

必须包含：

- AI provider。
- DashScope base URL。
- DashScope API key 输入。
- LLM base URL。
- LLM model。
- 默认图片模型。
- 默认视频模型。
- provider 配置状态。

要求：

- 已配置 key 只显示已设置状态，不回显明文。
- 保存后刷新配置状态。
- 前端不保存明文 key 到代码。

### 6.3 项目列表与创建

必须包含：

- 新建项目表单。
- 项目列表。
- 项目切换。
- 当前项目 URL 路由。

要求：

- 创建项目后自动进入项目页。
- 选中项目后刷新页面仍能打开该项目。
- 不存在项目 ID 时应回退到可用项目或空状态。

### 6.4 剧本页

必须包含：

- 标题编辑。
- 剧本原文编辑。
- 工作流选择。
- 保存按钮。
- 分析剧本按钮。
- 分析结果概要展示。

要求：

- 剧本文本区域不能太窄。
- 保存和分析是两个动作。
- 分析任务入队后应刷新任务记录。

### 6.5 美术方向页

必须包含：

- 风格选择。
- 正向 prompt。
- 负向 prompt。
- 色彩/镜头语言等配置。
- AI 推荐或自定义风格展示。
- 保存按钮。

### 6.6 资产页

必须包含：

- 一键补齐资产。
- 角色资产区。
- 场景资产区。
- 道具资产区。
- 新增资产表单。
- 资产卡片。
- 图片槽位。
- 图片变体条。
- 视频预览区。

视觉要求：

- 页面可以宽松一些，不要过度紧凑。
- 角色的全身图、三视图、头像必须一眼可见。
- 变体缩略图要有明确选中态。
- 删除/收藏等高频操作使用图标按钮。

### 6.7 分镜页

必须包含：

- AI 拆镜输入。
- 手动添加镜头。
- 镜头列表。
- 每个镜头的文本编辑区。
- 分镜图预览。
- 视频预览。
- 镜头操作按钮。

要求：

- 镜头删除前可直接删除，不需要二次页面跳转。
- 上传图片使用文件选择控件。
- 抽末帧按钮在没有视频时禁用。

### 6.8 成片页

必须包含：

- 拼接视频按钮。
- 导出按钮。
- 合成视频预览。
- 镜头时间线。

要求：

- 拼接失败时要展示任务错误。
- 成功后刷新仍能看到成片。

### 6.9 分集页

必须包含：

- 当前项目所属系列。
- 创建系列。
- 选择系列。
- 加入当前项目。
- 移出当前分集。
- 系列集数列表。
- 点击集数切换项目。

## 7. 任务记录要求

任务记录是核心功能，不是调试信息。

必须满足：

- 任务创建后立即出现在任务列表。
- 任务 pending/processing/completed/failed 都要可见。
- 任务刷新页面后仍存在。
- 任务可删除。
- 任务失败必须展示后端错误。
- 任务完成必须能通过刷新项目看到结果回写。

前端行为：

- 当前项目页每 3 秒轮询任务。
- 每次用户触发任务后立即刷新任务列表。
- 用户可手动点击刷新任务。
- 删除任务后任务列表立即更新。

## 8. Provider 与配置要求

图片、视频、LLM、音频都必须通过配置接入。

### 图片生成

必须支持：

- DashScope 图片生成。
- 外部 `ASSET_PROVIDER_ENDPOINT`。
- prompt。
- model。
- parameters。
- reference image URLs。

### 视频生成

必须支持：

- DashScope I2V。
- DashScope R2V。
- 外部 `VIDEO_PROVIDER_ENDPOINT`。
- image URL。
- reference image URLs。
- reference video URLs。
- model。
- duration。
- ratio/resolution。

### LLM

必须支持：

- DashScope OpenAI compatible endpoint。
- `LLM_BASE_URL`。
- `LLM_MODEL`。
- `LLM_API_KEY` 或 DashScope key。

### 音频

必须支持：

- 外部 `AUDIO_PROVIDER_ENDPOINT`。
- 未配置时真实失败，不返回假音频。

## 9. 数据持久化要求

MongoDB 必须保存：

- 项目。
- 系列。
- 任务。
- 图片变体。
- 视频变体。
- 分镜。
- 模型设置。
- Prompt 配置。
- 拼接结果。

刷新页面后必须恢复：

- 项目列表。
- 当前项目。
- 剧本原文。
- 资产。
- 变体选择状态。
- 任务记录。
- 分集关系。
- 成片 URL。

## 10. 安全要求

- 密钥只能通过环境变量或运行时配置保存。
- API 文档和前端代码不得出现真实密钥。
- 前端不得将密钥写入 localStorage。
- 后端配置查询不得返回已保存密钥明文。
- 文件上传必须由后端保存并返回受控 `/files/...` URL。
- 认证启用时，业务 API 必须验证 Bearer token。

## 11. 前端体验要求

- 页面不能空白；接口失败时要展示错误提示。
- 页面布局应按工作流分区，避免过度紧凑。
- 图片、视频、音频必须有预览入口。
- 生成按钮必须在缺必要输入时禁用。
- 长任务不能阻塞页面。
- 用户触发生成后应看到任务记录。
- 任务完成后应看到结果回显。
- 表单保存后应刷新项目状态。

## 12. 验收用例

### 用例 1：新建并解析剧本

步骤：

1. 新建项目，填写标题、剧本、工作流。
2. 点击分析剧本。
3. 等待任务完成。
4. 刷新页面。

期望：

- 项目仍存在。
- 剧本原文仍存在。
- 角色、场景、道具、分镜被写回。
- 任务记录中有 `analysis` 任务。

### 用例 2：资产生成与回显

步骤：

1. 进入资产页。
2. 新增角色。
3. 点击生成全身图。
4. 等待任务完成。
5. 刷新页面。

期望：

- 角色全身图区显示图片。
- 图片在变体列表中。
- `selected_image_id` 指向当前图。

### 用例 3：角色三视图和头像

步骤：

1. 角色已有全身图。
2. 点击一键补齐资产。
3. 等待任务完成。
4. 刷新页面。

期望：

- 三视图生成。
- 头像特写生成。
- 生成任务 payload 中使用全身图作为参考。

### 用例 4：资产变体操作

步骤：

1. 上传一张资产图。
2. 收藏该变体。
3. 删除该变体。
4. 刷新页面。

期望：

- 收藏状态保存。
- 删除后变体消失。
- 如果删除的是选中图，选中状态被自动清理或切到下一张。
